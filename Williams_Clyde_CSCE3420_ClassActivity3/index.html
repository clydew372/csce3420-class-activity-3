Why structure matters

Semantic HTML gives each region a meaningful role that browsers, assistive technology, and people can understand.

This project focuses on clear document structure and accessible choices that remain useful beyond visual styling.

Coursework map

The activity moves from document foundations to working evidence for navigation, accessibility, and validation.

Start with meaning

Choose elements for the role their content plays, then use CSS later to control presentation. A section groups related ideas, while an article can stand on its own.

Accessibility checkpoint

Ask whether the structure still makes sense when visual appearance is unavailable. Useful labels, headings, and alternative text make the same content easier to navigate.

Tools and materials

These topics support a page that communicates clearly to both people and browsers.

  • Semantic landmarks and heading hierarchy
  • Accessible images and alternative text
  • Relative, fragment, and external links
  • Forms, tables, and validation

Development workflow

The ordered steps reflect the sequence used to build and verify this project.

  1. Plan the document structure and content purpose.
  2. Write the HTML5 foundation and semantic landmarks.
  3. Add links, media, lists, tables, and form controls.
  4. Inspect the DOM, repair debug markup, and validate.
  5. Commit meaningful stages and publish the project.
